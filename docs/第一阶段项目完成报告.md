系统支持用户注册和登录、问卷创建与管理、四种题型、按配置执行的条件跳转、登录后填写问卷、匿名身份保护、重复提交控制、答卷保存、整份问卷统计和单题统计，并提供了可以操作和演示这些功能的前端页面。

3.系统设计

3.1技术架构

项目使用以下技术：

Node.js：JavaScript运行环境；

Express：HTTP服务和路由；

MongoDB：业务数据库；

Mongoose：Schema、索引、查询和数据校验；

JSON Web Token：登录身份认证；

bcryptjs：密码哈希；

HTML、CSS、原生JavaScript：前端页面；

Jest 和 Supertest：自动化API测试。

系统采用分层结构：

```text
浏览器页面
    ↓ HTTP 和 JSON
Express 路由
    ↓
JWT 认证中间件
    ↓
业务控制器
    ↓
答案和路径校验服务
    ↓
Mongoose 模型
    ↓
MongoDB
```

3.2后端结构

`src/routes/`：定义API路径；

`src/middleware/`：处理JWT认证；

`src/controllers/`：实现认证、问卷、题目、答卷和统计逻辑；

`src/services/`：实现答案校验和填写路径计算；

`src/models/`：定义MongoDB Schema和索引；

`src/app.js`：配置Express应用；

`src/server.js`：连接MongoDB并启动服务。

3.3前端结构

前端主要包括：

 系统首页：登录、注册、问卷列表和题目管理；

公开问卷页：问卷读取、逐题填写、条件跳转和提交；

统计页面：总答卷数、四种题型统计和单题筛选。

4MongoDB设计

4.1集合划分

系统主要使用四个集合：

| 集合          | 用途                           |
| ------------- | ------------------------------ |
| `users`     | 用户名和密码哈希               |
| `surveys`   | 问卷基本信息、状态和填写配置   |
| `questions` | 题目、选项、校验规则和跳转规则 |
| `responses` | 答卷、实际路径和历史快照       |

4.2 users集合

主要字段：

- `username`；
- `passwordHash`；
- `createdAt`；
- `updatedAt`。

4.3 surveys集合

主要字段：

- `ownerId`；
- `title`；
- `description`；
- `allowAnonymous`；
- `allowMultipleSubmissions`；
- `status`；
- `publicId`；
- `deadline`；
- `publishedAt`；
- `closedAt`；
- `schemaVersion`。

主要索引：

- `publicId` 唯一索引；
- `{ ownerId: 1, createdAt: -1 }`；
- `{ status: 1, deadline: 1 }`。

4.4 questions集合

主要字段：

- `surveyId`；
- `order`；
- `type`；
- `title`；
- `required`；
- `options`；
- `validation`；
- `jumpRules`。

使用 `{ surveyId: 1, order: 1 }` 唯一复合索引，防止同一问卷出现重复顺序。

4.5responses集合

主要字段：

- `surveyId`；
- `respondentId`；
- `anonymous`；
- `answers`；
- `visitedQuestionIds`；
- `surveyVersion`；
- `uniqueSubmissionKey`；
- `submittedAt`。

答案嵌入答卷文档中，并保存题目标题、题型和选择题选项快照。

主要索引：

- `uniqueSubmissionKey` 唯一稀疏索引；
- `{ surveyId: 1, submittedAt: -1 }`；
- `{ surveyId: 1, respondentId: 1 }`。

4.6 为什么使用MongoDB

问卷题型具有不同的校验字段，答案值也可能是字符串、数字或数组。MongoDB文档结构能够自然保存这些不同结构。

`validation`、`jumpRules` 和 `answers` 可以作为嵌套文档保存。第二阶段新增题型或校验规则时，可以增加可选字段，并结合版本字段兼容旧数据。

如果使用关系数据库，需要建立较多题型表、选项表、规则表和答案表，并使用多次连接查询恢复一份问卷或答卷。本项目的业务对象更适合MongoDB的文档模型。

5.条件跳转设计

跳转规则保存在 `questions.jumpRules` 中，由创建者配置。

每条规则包括：

- `operator`；
- `value`；
- `action`；
- `targetQuestionId`；
- `priority`。

支持的主要规则：

- 单选题：`equals`；
- 多选题：`containsAny`、`containsAll`；
- 数字题：`equals`、`gt`、`gte`、`lt`、`lte`；
- 文本题：`equals`。

规则按 `priority` 从小到大检查，只执行第一条命中的规则。

`action` 支持：

- `goto`：进入指定后续题目；
- `submit`：提前结束并提交。

没有规则命中时，进入顺序中的下一题。

保存规则时，后端检查：

- 操作符是否适用于当前题型；
- 条件值是否合法；
- 优先级是否重复；
- 目标是否存在；
- 目标是否属于同一问卷；
- 是否跳转到自身；
- 是否跳转到前面的题目；
- 是否形成显式循环。

第一阶段只允许 `goto` 跳转到 `order` 更大的后续题目。这样可以避免“向前跳转加默认下一题”形成隐含循环。原有有向图循环检测继续保留。

6 校验和答卷提交设计

6.1题型校验

1 单选题检查：

答案必须是字符串；

答案必须是有效 `optionId`；

必答题必须选择选项。

2 多选题检查：

答案必须是数组；

不能重复选择同一选项；

所有选项必须有效；

满足最少和最多选择数量。

固定选择数量通过把 `minSelections` 和 `maxSelections` 设置为相同数值实现。

3 文本题检查：

答案必须是字符串；

去除首尾空格；

满足最少和最多字符数。

4 数字题检查：

答案必须是有限数字；

满足最小值和最大值；

根据配置检查是否为整数。

6.2validation规范化

不同题型只保存和返回适用于自身的校验字段：

1单选题：不保存校验字段；

2多选题：选择数量字段；

3文本题：文本长度字段；

4数字题：数值范围和整数限制。

6.3填写路径计算

提交答卷时，后端从第一题重新计算完整路径：

1. 记录当前题；
2. 校验必答要求；
3. 校验当前题答案；
4. 按优先级匹配跳转规则；
5. 根据 `goto`、`submit` 或默认下一题继续；
6. 直到提前提交或没有下一题；
7. 检查答案中是否包含未访问的题目。

被条件跳转跳过的必答题不参与本次必答校验。

6.4重复提交

禁止重复提交时生成：

```text
uniqueSubmissionKey = surveyId:respondentId
```

MongoDB 唯一稀疏索引阻止并发重复提交。

允许重复提交时不创建该字段，因此可以保存多份答卷。

10 遇到的问题和解决办法

10.1 MongoDB服务停止

问题：

MongoDB 已安装，但 Windows 服务停止，导致 `mongosh` 和 Jest 测试服务器无法连接。

解决方法：

使用管理员 PowerShell 启动 MongoDB，并通过 `{ ok: 1 }` 验证连接。测试启动超时时先检查数据库服务，没有通过增加测试超时掩盖环境故障。

10.2npm镜像不支持Audit API

问题：

本地 npm registry 使用 npmmirror，执行 `npm audit` 返回 404 和 `NOT_IMPLEMENTED`。

解决方法：

保留日常 registry，只在 `audit:prod` 脚本中显式使用 npm 官方 registry。最终结果为 `found 0 vulnerabilities`。

10.3跳转循环检查不完整

问题：

初始有向图只包含显式 `goto`，没有把未命中规则时的默认下一题路径加入图中，向前跳转可能与默认路径形成隐含循环。

解决方法：

只允许 `goto` 指向 `order` 更大的后续题目，并保留显式循环检测作为额外保护。

10.4登录和注册同时显示

问题：

初版页面同时显示登录和注册表单，用户容易误认为出现两个登录框。

解决方法：

将认证区域改为单卡片的登录和注册标签切换。

10.5浏览器原生校验阻断中文提示

问题：

数字输入框的原生 `min`、`max` 和 `step` 校验可能在 JavaScript 事件前阻断提交，使页面保留旧错误信息。

解决方法：

为答卷表单增加 `novalidate`，统一使用项目 JavaScript 显示中文校验提示，后端继续执行最终校验。
