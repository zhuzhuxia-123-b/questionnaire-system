第二阶段在第一阶段在线问卷系统的基础上继续开发，不重新创建独立项目，并保留原有用户、问卷、题目和答卷数据。

 4 MongoDB 数据库设计

第一阶段已有集合：

```text
users
surveys
questions
responses
```

第二阶段新增集合：

```text
questionItems
questionVersions
questionShares
questionBanks
schemaMigrations
```

4.1 questionItems

表示逻辑上的同一道题，主要保存：

```text
ownerId
currentVersionId
latestVersionNumber
status
legacyQuestionId
```

4.2 questionVersions

保存题目每个版本的具体内容：

```text
questionItemId
versionNumber
parentVersionId
restoredFromVersionId
type
title
options
validation
changeNote
```

使用以下唯一索引避免版本号重复：

```text
questionItemId + versionNumber
```

4.3 questionShares

保存题目共享关系：

```text
questionItemId
ownerId
sharedWithUserId
permission
status
sharedAt
revokedAt
```

同一道题和同一接收者之间只有一条共享记录。

4.4 questionBanks

保存用户建立的题目库。

题目库只保存：

```text
questionItemId
preferredVersionId
```

不复制题目正文。

4.5 questions 集合调整

问卷中的题目实例增加：

```text
questionItemId
questionVersionId
contentSource
schemaVersion
```

同时继续保存题目内容快照，保证逻辑题目更新后旧问卷不受影响。

 5 题目版本设计

历史版本创建后不允许直接修改或删除。

编辑可复用题目时，系统创建递增的新版本。例如：

```text
v1 → v2 → v3
```

新版本的 `parentVersionId` 指向修改前的当前版本。

恢复历史版本时，也不会把当前版本指针直接改回旧版本，而是复制历史内容创建新版本。

例如从 v2 恢复 v1 内容：

```text
v1 → v2 → v3
```

其中：

```text
v3.parentVersionId = v2
v3.restoredFromVersionId = v1
```

这样既恢复了历史内容，又保留了完整版本记录。

 6 题目复用和旧问卷保护

将可复用题目加入问卷时，必须明确选择：

```text
questionItemId
questionVersionId
```

后端将该版本的题目内容复制到 Question 快照，并保存：

```text
contentSource = library
schemaVersion = 2
```

问卷中的以下字段仍由题目实例单独管理：

```text
order
required
jumpRules
```

以后逻辑题目创建新版本时：

- 已有问卷继续引用原 `questionVersionId`；
- 已有问卷题目内容不变；
- 已发布问卷不自动升级；
- 已有答卷不受影响。

 7 题目共享和题目库
 7.1 题目共享

题目所有者可以按用户名共享题目。

接收者只有 `use` 权限，可以：

查看收到的共享；
查看题目版本；
把指定版本加入本人草稿问卷。

接收者不能：

创建新版本；
恢复历史版本；
修改所有者题目；
将共享继续转发给其他用户。

撤销共享采用软撤销。撤销后接收者不能继续复用，但已经加入问卷的题目快照不会删除。

再次共享时重新激活原记录，不创建重复关系。

 7.2 题目库

用户可以：

创建本人题目库；
修改名称和说明；
加入本人可复用题目；
移除题目；
设置推荐版本；
将指定版本加入本人草稿问卷。

从题目库移除题目只删除引用，不删除逻辑题目、历史版本或已有问卷数据。

8 跨问卷统计

跨问卷统计首先按照：

```text
Survey.ownerId = 当前用户ID
```

过滤，只统计当前用户拥有的问卷。

题目被共享后，题目所有者仍然不能查看其他用户问卷中的答卷。

不同题目版本不强制合并，而是按：

```text
questionVersionId
```

分别统计。

接口返回：

```text
surveyCount
questionInstanceCount
responseCount
answerOpportunityCount
totalAnswers
notAnsweredCount
```

其中：

```text
notAnsweredCount =
answerOpportunityCount - totalAnswers
```

`answerOpportunityCount` 表示各题目实例对应问卷答卷数之和，适用于同一道逻辑题目在同一问卷中出现多个实例的情况。

单选题和多选题在同一版本内按稳定的 `optionId` 统计。

文本题返回回答列表。

数字题返回平均值、最小值和最大值。

统计接口不返回：

```text
respondentId
答卷者 username
uniqueSubmissionKey
```

 9 旧数据迁移

迁移前数据库数据为：

```json
{
  "users": 6,
  "surveys": 7,
  "questions": 12,
  "responses": 3
}
```

迁移脚本默认使用 dry-run，不写入数据库：

```powershell
node `
    '.\scripts\migrate-stage2-question-versioning.js' `
    --dry-run
```

只有明确传入 `--apply` 时才执行迁移：

```powershell
node `
    '.\scripts\migrate-stage2-question-versioning.js' `
    --apply
```

迁移后：

```json
{
  "users": 6,
  "surveys": 7,
  "questions": 12,
  "responses": 3,
  "questionItems": 12,
  "questionVersions": 12,
  "schemaMigrations": 1
}
```

原有集合数量没有减少。

引用检查结果：

```json
{
  "questionsMissingReferences": 0,
  "responsesMissingReferences": 0,
  "surveysNotUpgraded": 0,
  "itemsMissingCurrentVersion": 0
}
```

第二次执行迁移时：

```json

  "processedCount": 0,
  "skippedCount": 22,
  "failedCount": 0

```

说明迁移可以重复执行，不会生成重复题目或版本。

11 开发中遇到的问题

11.1 Mongoose 字段名称问题

迁移模型最初使用 `errors` 字段，模型加载时出现 Mongoose 保留路径警告。

解决方法：

```text
errors → errorDetails
```

11.2 sparse 唯一索引问题

新建 QuestionItem 时，`legacyQuestionId` 曾被显式保存为 `null`，可能与 sparse 唯一索引产生冲突。

解决方法：

新建第二阶段题目时不保存该字段，只有迁移第一阶段旧题目时才写入真实 ID。

11.3 新答卷缺少版本引用

第二阶段跨问卷统计测试最初得到：

```text
Expected totalAnswers: 2
Received totalAnswers: 0
```

检查发现新答卷答案快照没有保存：

```text
questionItemId
questionVersionId
```

修改答案校验和答卷控制器后，新答案能够保存版本引用，跨问卷统计测试通过。

11.4 PowerShell 中文 JSON

PowerShell 中的 byte 数组曾被展开成数字字符串，导致 Express 无法解析请求体。

解决方法是显式创建强类型 UTF-8 数组：

```powershell
[byte[]]$body =
    [System.Text.Encoding]::UTF8.GetBytes(
        $json
    )
```
