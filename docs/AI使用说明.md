- 得到的代码或结果；

- 修改内容；

## 3 AI 输出中存在的问题

AI 输出并非全部可以直接采用，实际开发中发现了以下问题或不足。

### 3.1 没有处理 bcrypt 的 72 字节限制

初版注册代码只检查密码不少于 8 个字符，没有检查 bcrypt 只使用前 72 个 UTF-8 字节的问题。

如果不处理，两个只在 72 字节之后不同的密码可能产生相同的有效验证结果。

### 3.2 安全审计命令没有考虑本地 registry

AI 最初建议：

```text
npm audit --omit=dev
```

本机使用 npmmirror，但该镜像没有实现 npm Audit API，实际返回 404 和 `NOT_IMPLEMENTED`。

### 3.3 validation 初始设计会产生无关字段

初版 `validationSchema` 为 `integerOnly` 设置了默认值。由于四种题型共用同一个子 Schema，多选题和文本题也可能出现 `integerOnly: false`。

这会增加 MongoDB 文档冗余，并让接口使用者误解字段含义。

### 3.4 初始循环检测没有覆盖默认顺序路径

初版循环检测只把显式 `goto` 作为有向图的边，没有包含规则未命中时进入下一题的默认路径。

因此，“后面题目跳到前面题目”可能和默认顺序形成隐含循环。

### 3.5 初版测试连接方式出现超时

初版测试在 Jest 生命周期钩子中直接连接和清理 MongoDB，实际运行时发生 30 秒超时，并触发数据库名称保护错误。

该方案在当前运行环境中不稳定。

### 3.6 初版认证界面容易产生误解

AI 初版前端同时显示登录和注册表单，实际打开页面时看起来像有两个登录框。

### 3.7 浏览器原生校验影响自定义提示

公开填写页面中的数字输入框使用原生 `min`、`max` 和 `step` 后，浏览器可能在 JavaScript 提交事件之前阻止提交，导致旧的自定义错误提示没有及时更新。

### 3.8 公开题目序列化需要兼容旧数据

公开问卷接口初版直接返回题目的 `validation`，旧题目文档中可能存在不属于当前题型的字段。

### 3.9 文档生成后仍需人工检查

API 文档整理过程中出现过完整内容重复和残缺版本混入的问题。仅检查某个接口字符串存在无法发现这种问题，还需要检查标题数量、章节数量和总行数。

## 4 学生对 AI 输出的修改

### 4.1 明确匿名的实际含义

学生提出：

- 匿名不表示免登录；
- 系统内部可以保存 `respondentId`；
- `respondentId` 用于认证和限制重复提交；
- 问卷创建者不能通过答卷或统计接口获得匿名填写者身份；
- 匿名保护必须由后端控制响应字段。

该设计解决了“填写前需要登录”和“支持匿名填写”之间的解释问题。

### 4.2 增加项目元数据

学生在 `package.json` 中增加：

```json
{
  "private": true,
  "engines": {
    "node": ">=22"
  }
}
```

`private` 防止课程项目被误发布，`engines` 明确实际验证的 Node.js 环境要求。

### 4.3 修正安全审计脚本

学生根据 npmmirror 的真实错误，将脚本修改为：

```text
npm audit --omit=dev --registry=https://registry.npmjs.org
```

该修改只影响安全审计，没有改变日常 npm registry。

### 4.4 增加 bcrypt 字节边界检查

学生在注册接口中增加：

```javascript
bcrypt.truncates(password)
```

检测到密码会被截断时返回 400，并明确按 UTF-8 字节判断。

### 4.5 规范化 validation

学生：

- 删除 `integerOnly` 的默认值；
- 建立不同题型允许字段的映射；
- 在创建、编辑和接口序列化时执行筛选；
- 对公开问卷接口执行相同筛选。

最终结果为：

- 单选题不返回校验字段；
- 多选题只返回选择数量；
- 文本题只返回长度限制；
- 数字题只返回数值限制。

### 4.6 增加只向后续题目跳转的规则

学生发现显式跳转图没有覆盖默认顺序路径，提出：

```text
targetQuestion.order 必须大于当前 question.order
```

该规则防止跳回前面题目，并保留原有循环检测。

### 4.7 增加数据保留策略

学生补充设计：

- 草稿题目可以删除；
- 发布后的题目不物理删除；
- 已发布和已关闭问卷保留；
- 问卷关闭不级联删除答卷；
- 答卷快照长期保留。

### 4.8 增加 notAnsweredCount

学生发现只有 `responseCount` 和 `totalAnswers` 不方便解释条件跳转后的统计，因此增加：

```text
notAnsweredCount = responseCount - totalAnswers
```

学生没有将其命名为 `skippedCount`，因为未回答也可能来自非必答题主动留空。

### 4.9 改进认证界面

学生根据实际使用体验，将同时显示的登录和注册表单改为单卡片标签切换。

### 4.10 统一前端中文校验

学生为答卷表单增加 `novalidate`，让 JavaScript 统一显示中文错误信息，同时保留后端最终校验。

## 6 AI 代码的采用情况

不同步骤采用 AI 输出的程度不同。

部分步骤主要采用 AI 提供的代码，例如：

- 基础 Express 配置；
- Mongoose 模型初稿；
- 认证接口初稿；
- 问卷和题目接口初稿；
- 前端统计页面。

部分步骤在 AI 代码基础上进行了修改，例如：

- 注册密码字节限制；
- validation 规范化；
- 跳转方向限制；
- 统计未回答数量；
- 前端认证界面；
- 公开填写校验；
- 公开题目序列化。

部分步骤没有生成业务代码，例如：

- 环境检查；
- MongoDB 服务诊断；
- 需求分析；
- README 和提交风险检查。

日志中分别记录了“未修改”“有修改”和“未生成业务代码”，没有把所有步骤统一写成已修改。

## 7 验证 AI 输出的方法

AI 输出没有仅凭阅读直接判定正确，而是使用以下方法验证：

- `node --check` 检查 JavaScript 语法；
- `require('./src/app')` 检查模块加载；
- `npm list --depth=0` 检查依赖；
- `npm audit --omit=dev` 检查运行依赖；
- `mongosh` 检查 MongoDB 连接和保存数据；
- `Invoke-RestMethod` 检查 API 状态码和响应；
- 使用第二个用户验证所有权隔离；
- 查询 MongoDB 检查密码哈希、快照和提交键；
- 浏览器检查前端交互和控制台；
- Jest 和 Supertest 执行自动化测试；
- 检查测试端口是否释放；
- 检查测试数据库是否清理；
- 使用 `Select-String` 检查文档章节和关键字段。

## 8 使用 AI 的总结

AI 显著提高了需求整理、代码编写、错误定位、测试设计和文档整理的效率，但 AI 输出仍需要人工判断和真实运行验证。

本项目中，AI 适合：

- 快速生成结构化初稿；
- 解释命令和代码；
- 提供常见实现方案；
- 根据错误输出辅助定位问题；
- 整理文档格式和测试步骤。

AI 不能代替：

- 对作业要求的最终判断；
- 对隐私和业务语义的设计；
- 对数据库历史数据的考虑；
- 对实际界面体验的判断；
- 对运行环境问题的检查；
- 对代码和文档的最终验收。

最终项目是在 AI 提供初稿和建议的基础上，由学生亲自操作、检查、修改和验证完成的。
