# AI 使用说明

## 1 说明目的

本项目在第一阶段和第二阶段开发过程中使用了生成式 AI 辅助完成需求分析、数据库设计、代码示例、测试设计、错误诊断和项目文档整理。

AI 主要作为开发辅助工具使用。项目中的命令由本人亲自执行，业务文件由本人亲自创建或修改，AI 提供的结果需要经过阅读、验证和必要修改后才能采用。

详细的逐次 Prompt、Result、是否修改、修改内容和验证结果记录在：

```text
docs/AI使用日志.md
```

## 3 AI 使用流程

项目采用以下 AI 协作流程：

```text
阅读作业要求
    ↓
向 AI 提出明确任务
    ↓
AI 给出设计、代码或命令
    ↓
本人阅读和理解
    ↓
本人创建或修改文件
    ↓
执行语法检查
    ↓
执行接口或页面动态测试
    ↓
发现问题并提出修改意见
    ↓
修改代码或设计
    ↓
运行 Jest 回归测试
    ↓
记录真实 AI 使用过程
```

每个较完整的功能阶段使用独立编号记录，例如：

```text
AI-001
AI-002
……
AI-031
AI-032
```

## 6 AI 出现的问题和不足

AI 提供的结果并非始终正确，本项目中出现过以下问题。

### 6.1 npm Audit registry 问题

AI 最初建议直接执行：

```text
npm audit --omit=dev
```

但当前 npm registry 是：

```text
https://registry.npmmirror.com/
```

该镜像不支持 Audit API，导致审计失败。

本人根据实际错误把脚本改为：

```text
npm audit --omit=dev --registry=https://registry.npmjs.org
```

最终结果：

```text
found 0 vulnerabilities
```

### 6.2 未区分服务未启动和代码错误

一次健康接口检查失败，AI 需要进一步确认是服务未启动还是代码错误。

实际原因是没有运行：

```text
npm run dev
```

启动服务后接口正常。

这说明环境问题和代码问题必须分别诊断。

### 6.3 PowerShell byte[] 展开问题

AI 最初提供的 UTF-8 请求体辅助函数在 PowerShell 管道中被展开，导致请求体变成数字字符串，例如：

```text
123 13 10 ...
```

Express 无法解析为 JSON。

本人改为直接生成强类型数组：

```powershell
[byte[]]$body =
    [System.Text.Encoding]::UTF8.GetBytes(
        $json
    )
```

修改后中文 JSON 请求正常。

### 6.4 非法 JSON 曾返回 500

动态测试发现非法 JSON 被错误处理为服务器内部错误。

本人检查并修改 Express 错误处理中间件，使 JSON 解析错误返回：

```text
400 Bad Request
```

而不是 `500`。

### 6.5 Mongoose 保留路径问题

AI 最初在 SchemaMigration 中使用：

```text
errors
```

模型加载时发现该名称可能与 Mongoose 内部错误路径冲突。

本人将其改为：

```text
errorDetails
```

并同步修改迁移脚本和数据库设计文档。

### 6.6 findOneAndUpdate 返回选项

AI 初始迁移脚本使用：

```javascript
new: true
```

本人结合当前 Mongoose 版本，将两处修改为语义更明确的：

```javascript
returnDocument: 'after'
```

### 6.7 legacyQuestionId 的 null 冲突

AI 模型代码最初使第二阶段新 QuestionItem 保存：

```text
legacyQuestionId: null
```

由于该字段存在 sparse 唯一索引，多个显式 `null` 可能导致唯一性冲突。

本人删除 `default: null`，让第二阶段新题目不保存该字段。只有迁移旧题目时才写入真实旧题目 ID。

### 6.8 新答卷缺少版本引用

第二阶段跨问卷统计测试最初失败：

```text
Expected totalAnswers: 2
Received totalAnswers: 0
```

原因不是统计公式错误，而是新答卷答案快照缺少：

```text
questionItemId
questionVersionId
```

本人修改：

```text
responseValidationService.js
responseController.js
```

让新答案保存版本引用，并根据题目结构设置 Response 的 `schemaVersion`。

修改后第二阶段 6 项测试全部通过。

### 6.9 文档曾出现重复内容

生成 API 文档时，曾出现多份内容重复追加，导致标题和章节重复。

本人通过标题数量和总行数检查发现问题，删除重复和残缺内容，只保留一份完整文档。

### 6.10 部分操作流程过于复杂

AI 在数据库备份、临时测试数据清理和 Git 步骤中，曾一次提供过多命令，使流程难以理解。

本人提出：

- 一次只处理当前必要步骤；
- 先做只读诊断；
- 只删除已经确认 ID 的临时对象；
- 不每一步都提交或推送 Git；
- 一个完整功能完成后统一测试和记录日志。

之后流程改为按完整功能阶段推进。

## 7 本人提出并完成的修改

### 7.1 匿名语义

本人提出：

匿名表示对问卷创建者隐藏身份，不表示允许未登录填写。

系统内部可以保存 `respondentId` 用于认证和重复提交限制，但统计和匿名答卷接口不得返回身份信息。

### 7.2 数据保留和删除策略

本人提出：

- 已发布和已关闭问卷不物理删除；
- 题目只能在草稿状态删除；
- 问卷关闭不级联删除答卷；
- 历史答案快照长期保留。

### 7.3 bcrypt 72 字节保护

本人发现只检查密码字符数量不能处理 bcrypt 的 UTF-8 72 字节上限。

本人增加：

```javascript
bcrypt.truncates(password)
```

检查，防止密码被静默截断。

### 7.4 validation 按题型规范化

本人发现共用 validation Schema 会让非数字题出现：

```text
integerOnly: false
```

等无关字段。

本人修改 Question 模型和控制器，使四种题型只保存适用字段。

### 7.5 向前推进的跳转规则

本人发现只检查显式 `goto` 边可能遗漏默认顺序路径形成的隐含循环。

本人提出：

```text
goto 只能跳转到 order 更大的后续题目
```

同时保留原循环检测作为额外保护。

### 7.6 统计未回答数量

本人提出为每道题增加：

```text
notAnsweredCount
```

并且不命名为 `skippedCount`，因为未回答也可能是非必答题未填写，不一定是条件跳转。

### 7.7 登录和注册界面

本人在实际使用中发现登录和注册表单同时显示容易被误认为两个登录框。

本人把认证区域改为单卡片标签切换。

### 7.8 中文校验提示

本人发现浏览器原生 `min`、`max` 和 `step` 校验可能阻止 JavaScript 提交事件并保留旧提示。

本人为表单增加：

```html
novalidate
```

统一使用 JavaScript 的中文错误信息。

### 7.9 公开 validation 规范化

本人提出公开问卷接口也应该按题型过滤 validation，避免旧题目返回无关字段。

本人修改公开题目序列化逻辑。

## 8 本人在第二阶段提出的设计

### 8.1 历史版本真正不可变

本人提出：

- 不提供历史版本修改接口；
- 不提供历史版本删除接口；
- 编辑逻辑题目时创建新版本；
- 恢复历史版本时复制内容生成新版本；
- 不能直接把 `currentVersionId` 改回旧版本。

### 8.2 显式保存采用的版本

本人提出：

从可复用题目加入问卷时必须明确保存实际采用的：

```text
questionVersionId
```

不能只读取不断变化的 `currentVersionId`。

Question 同时保存版本内容快照，保证旧问卷不自动升级。

### 8.3 共享生命周期

本人提出：

- 撤销共享只阻止以后继续复用；
- 已有 Question 快照不能被删除或修改；
- 共享使用软撤销；
- 再次共享时重新激活原记录；
- 不创建重复关系；
- `createdAt` 保留首次创建时间；
- `sharedAt` 表示最近激活时间；
- 已经 active 时重复共享不更新时间。

### 8.4 接收者权限边界

本人提出接收者只有 `use` 权限：

可以：

- 查看共享题目；
- 查看版本；
- 选择版本加入本人草稿问卷。

不能：

- 创建版本；
- 恢复版本；
- 撤销所有者共享；
- 归档所有者题目；
- 转发共享。

### 8.5 题目库引用式存储

本人提出题目库只保存：

```text
questionItemId
preferredVersionId
```

不复制题目正文。

修改推荐版本只影响以后选题建议，不影响已有问卷。

从题目库移除题目不删除逻辑题目、历史版本或已有问卷快照。

### 8.6 跨问卷统计权限

本人提出跨问卷统计必须先按：

```text
Survey.ownerId = req.user.id
```

过滤。

不能因为题目被共享，就让题目所有者查看其他用户问卷中的答卷。

### 8.7 跨版本统计

本人提出不同版本不能强行合并。

具体结果按：

```text
questionVersionId
```

分组，并支持查询指定版本。

选择题在同一版本内按稳定 `optionId` 统计，不能只按选项文字合并。

### 8.8 answerOpportunityCount

本人发现同一逻辑题目可能在一个问卷中出现多个实例，因此不能使用：

```text
responseCount - totalAnswers
```

计算未回答数。

本人提出：

```text
answerOpportunityCount =
各题目实例对应问卷答卷数之和
```

然后计算：

```text
notAnsweredCount =
answerOpportunityCount - totalAnswers
```

同时单独返回去重答卷数 `responseCount`。

### 8.9 安全迁移流程

本人提出迁移脚本：

- 默认 dry-run；
- 只有 `--apply` 才写数据；
- 显示实际数据库名；
- 拒绝空数据库名；
- 执行前检查引用；
- 支持重复运行；
- 第二次不能产生重复 QuestionItem 或 QuestionVersion。

### 8.10 精简第二阶段前端

本人提出第二阶段功能集中到：

```text
resources.html
```

使用简单标签切换，复用第一阶段 JWT 和 `api.js`。

不实现：

- 拖拽；
- 图表库；
- 公开市场；
- 复杂搜索；
- 高级视觉效果。

这样把时间集中在课程要求的数据库和后端逻辑上。

## 9 AI 生成代码的修改情况

项目中多数初始代码由 AI 提供结构或完整示例，本人亲自复制到项目、阅读并运行。

修改情况不是简单的“全部采用”或“全部重写”，主要分为三类。

### 9.1 未修改采用

部分代码通过语法、动态和回归测试后未修改采用，例如：

- 基础 Express 路由；
- 部分 Mongoose 模型；
- 第一阶段基本控制器；
- 第二阶段页面基础结构；
- 部分测试结构。

### 9.2 根据实际错误修改

包括：

- npm Audit registry；
- UTF-8 byte[]；
- 非法 JSON 状态码；
- `errors` 改为 `errorDetails`；
- `new: true` 改为 `returnDocument: 'after'`；
- `legacyQuestionId` 的 null；
- 答案快照版本引用。

### 9.3 根据个人设计修改

包括：

- 匿名含义；
- 数据保留策略；
- bcrypt 72 字节限制；
- validation 规范化；
- 向后续题目跳转；
- `notAnsweredCount`；
- 版本不可变；
- 恢复生成新版本；
- 显式版本入卷；

8. 帮助检查权限和敏感信息；
9. 帮助整理 API 和关键逻辑文档；
10. 减少重复编码和格式整理时间。

如果完全不使用 AI，版本管理、迁移、共享、题目库和跨问卷统计的实现与测试工作量会明显增加。

## 12 AI 使用的限制

AI 的限制包括：

1. 不了解本地服务是否已经启动；
2. 可能默认某个工具已经安装；
3. 可能给出不适用于当前 PowerShell 行为的命令；
4. 可能没有考虑当前 npm registry；
5. 可能使用与当前 Mongoose 版本不完全匹配的写法；
6. 可能遗漏跨集合数据写入；
7. 可能生成过长或重复的文档；
8. 临时数据清理命令需要特别谨慎；
9. AI 不能代替实际数据库检查；
10. AI 不能代替本人对业务规则的判断。

因此，AI 输出不能未经验证直接作为最终成果。
