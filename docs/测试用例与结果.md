## 3 测试隔离设计

### 3.1 独立测试数据库

自动化测试只允许连接：

```text
mongodb://127.0.0.1:27017/questionnaire_system_test
```

测试初始化和清理代码会检查实际数据库名称。

如果数据库名称不是：

```text
questionnaire_system_test
```

测试立即停止，避免误删除开发数据库。

### 3.2 独立测试端口

测试服务器使用：

```text
3101
```

开发服务器使用：

```text
3000
```

两个端口相互独立。

### 3.3 测试生命周期

测试开始前：

1. 连接测试数据库；
2. 清理旧测试数据；
3. 启动测试服务器；
4. 等待健康接口可用。

测试完成后：

1. 关闭测试服务器；
2. 清理测试数据库；
3. 断开 MongoDB 连接；
4. 检查 3101 端口是否仍被监听；
5. 检查测试数据库集合是否为空。

- 清理测试产生的显式 `null`。

修改后结果：

```text
PASS
```

结论：题目库引用式存储和数据删除边界正确。

## 18 TC-13 跨问卷单题统计

接口：

```http
GET /api/question-items/:questionItemId/cross-survey-statistics
```

可选版本筛选：

```http

```

测试数据包括：

- 同一逻辑题目的 v1 和 v2；
- 多个本人问卷；
- 同一问卷中的多个题目实例；
- 其他用户问卷；
- 共享题目；
- 单选、多选、文本和数字题。

预期汇总示例：

```text
surveyCount = 3
questionInstanceCount = 4
responseCount = 4
answerOpportunityCount = 6
totalAnswers = 5
notAnsweredCount = 1
```

测试步骤：

1. 查询逻辑题目的整体统计；
2. 检查只包含本人问卷；
3. 检查共享用户数据是否隔离；
4. 检查去重答卷数；
5. 检查多个题目实例的回答机会数；
6. 检查 v1 和 v2 分组；
7. 使用 `questionVersionId` 筛选；
8. 检查四种题型结果；
9. 检查敏感字段。

预期结果：

- 只统计当前用户拥有的问卷；
- 题目所有者不能看到其他用户问卷答卷；
- 共享接收者只能统计自己问卷；
- `responseCount` 为去重答卷数；
- `answerOpportunityCount` 按题目实例计算；
- `notAnsweredCount = answerOpportunityCount - totalAnswers`；
- 不同版本分别统计；
- 选择题在同一版本内按稳定 `optionId` 统计；
- 支持具体版本筛选；
- 不返回身份字段。

初次实际结果：

```text
5 项通过，跨问卷统计测试失败。
Expected totalAnswers: 2
Received totalAnswers: 0
```

原因：

新答卷答案快照没有保存：

```text
questionItemId
questionVersionId
```

跨问卷统计按这两个字段聚合，因此找不到新答卷答案。

修改：

1. 在 `responseValidationService.js` 中把题目引用写入答案快照；
2. 在 `responseController.js` 中根据问卷题目结构设置 Response 的 `schemaVersion`；
3. 保持第一阶段旧答卷兼容。

修改后实际结果：

```text
PASS
```

结论：本人问卷过滤、按版本统计和回答机会数计算正确。
