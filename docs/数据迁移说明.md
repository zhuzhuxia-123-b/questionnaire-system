# 第二阶段数据迁移说明

## 1 文档目的

第二阶段在第一阶段数据结构基础上增加：

- 可复用逻辑题目；
- 不可变题目版本；
- 题目共享；
- 题目库；
- 跨问卷统计；
- 新旧数据结构兼容。

本文件说明第一阶段旧数据的备份、迁移、验证、幂等性和回滚方案。

迁移脚本：

```text
scripts/migrate-stage2-question-versioning.js
```

迁移名称：

```text
stage2-question-versioning-v1
```

---

## 2 迁移原则

迁移遵守以下原则：

1. 不删除第一阶段集合；
2. 不删除第一阶段问卷、题目和答卷；
3. 为旧题目补充第二阶段引用；
4. 为旧答卷尽可能补充版本引用；
5. 保留旧题目和答案快照；
6. 默认只执行 dry-run；
7. 只有显式传入 `--apply` 才写数据库；
8. 迁移可以重复运行；
9. 第二次执行不能生成重复数据；
10. 迁移失败时保留错误记录；
11. 迁移前必须确认实际数据库名称；
12. 迁移后第一阶段功能和测试必须继续通过。

## 8 数据库名称保护

迁移脚本从 MongoDB 连接地址取得实际数据库名称。

执行前输出：

```json
{
  "migration": "stage2-question-versioning-v1",
  "mode": "dry-run",
  "host": "127.0.0.1",
  "database": "questionnaire_system"
}
```

保护规则：

1. 数据库名称不能为空；
2. 拒绝迁移系统数据库；
3. 显示实际数据库名称；
4. 用户应确认目标为 `questionnaire_system`；
5. 不允许误连接没有数据库名称的地址；
6. 不允许对测试数据库和正式数据库产生混淆。

执行只读检查时也应使用明确地址：

```text
mongodb://127.0.0.1:27017/questionnaire_system
```

不能只依赖当前 mongosh 默认数据库。

## 9 dry-run 检查逻辑

dry-run 执行以下只读检查：

1. 读取用户数量；
2. 读取问卷数量；
3. 读取旧题目数量；
4. 读取旧答卷数量；
5. 读取现有 QuestionItem 数量；
6. 读取现有 QuestionVersion 数量；
7. 检查 Question 的 surveyId；
8. 检查 Survey 的 ownerId；
9. 检查 Response 的 surveyId；
10. 检查答案中的 questionId；
11. 计算预计创建和修改数量；
12. 输出发现的问题；
13. 不调用写入操作。

## 11 正式迁移过程

### 11.1 为旧题目创建 QuestionItem

每个第一阶段旧 Question 对应一个 QuestionItem。

主要字段：

```text
ownerId = 旧问卷 ownerId
legacyQuestionId = 旧 Question._id
latestVersionNumber = 1
status = active
schemaVersion = 1
```

`legacyQuestionId` 用于保证同一旧题目不会重复迁移。

### 11.2 创建初始 QuestionVersion

每个旧 Question 创建一个版本号为 1 的 QuestionVersion。

复制字段：

```text
type
title
options
validation
```

不复制以下问卷专属字段：

```text
surveyId
order
required
jumpRules
```

### 11.3 建立当前版本引用

QuestionItem 保存：

```text
currentVersionId = 新 QuestionVersion._id
latestVersionNumber = 1
```

### 11.4 扩展旧 Question

旧 Question 保留原字段，同时增加：

```text
questionItemId
questionVersionId
contentSource
schemaVersion
```

迁移后的旧 Question 仍然保存内容快照。

### 11.5 扩展旧 Response

旧答卷保留：

- 原答案值；
- 题目标题快照；
- 选项快照；
- 原填写路径。

在能够确定题目引用时，为答案补充：

```text
questionItemId
questionVersionId
```

无法安全确定的旧字段不强制伪造。

### 11.6 扩展 Survey

旧问卷补充第二阶段所需的 Schema 版本信息，但不改变：

- 问卷所有者；
- 标题；
- 状态；
- 公开 ID；
- 发布时间；
- 关闭时间；
- 匿名设置；
- 重复提交设置。

## 15 幂等性设计

迁移脚本通过以下方式保证幂等：

1. QuestionItem 的 `legacyQuestionId` 使用 sparse 唯一索引；
2. QuestionVersion 使用 `questionItemId + versionNumber` 唯一索引；
3. SchemaMigration 的 `name` 使用唯一索引；
4. 使用 upsert 或先查询后写入；
5. 已迁移对象计入 `skippedCount`；
6. 不重复覆盖已存在的有效引用；
7. 不重复创建初始版本。

## 17 迁移过程中发现的问题和修改

### 17.1 Mongoose 保留路径警告

最初 SchemaMigration 使用字段：

```text
errors
```

该名称可能与 Mongoose 内部错误路径产生混淆。

人工修改为：

```text
errorDetails
```

并同步修改：

- SchemaMigration 模型；
- 迁移脚本；
- 数据库设计文档；
- 迁移结果检查。

### 17.2 findOneAndUpdate 返回语义

最初使用：

```javascript
new: true
```

为使当前 Mongoose 版本的语义更明确，人工修改为：

```javascript
returnDocument: 'after'
```

确保更新后取得最新文档。

### 17.3 数据库地址不明确

一次只读检查连接到了错误的默认数据库，得到全部数量为 0 的结果。

解决方法：

- 不把该结果视为迁移失败；
- 使用包含数据库名的完整 URI 重新检查；
- 明确输出实际数据库名称。

正确地址：

```text
mongodb://127.0.0.1:27017/questionnaire_system
```

### 17.4 legacyQuestionId 与 sparse 唯一索引

第二阶段新建 QuestionItem 不属于第一阶段旧题目，因此不应保存：

```text
legacyQuestionId: null
```

显式 `null` 可能参与唯一索引并产生冲突。

解决方法：

- 删除该字段的 `default: null`；
- 新建第二阶段题目时不写入该字段；
- 只有迁移旧题目时才设置真实的 `legacyQuestionId`。

## 19 回滚方案

### 19.1 回滚前提

迁移前已经使用 `mongodump` 保存第一阶段数据库备份。

### 19.2 回滚原则

如果迁移发生严重失败：

1. 停止开发服务；
2. 保留失败日志；
3. 确认备份路径；
4. 确认目标数据库名称；
5. 删除或更名失败数据库；
6. 使用 `mongorestore` 恢复备份；
7. 重新检查四个核心集合数量；
8. 在修复迁移脚本后先执行 dry-run。

### 19.3 恢复命令示例

以下命令仅作为恢复说明，实际执行前必须再次确认路径和目标数据库：

```powershell
$mongoRestoreExe =
    'C:\Program Files\MongoDB\Tools\100\bin\mongorestore.exe'

& $mongoRestoreExe `
    --uri `
    'mongodb://127.0.0.1:27017' `
    --nsFrom `
    'questionnaire_system.*' `
    --nsTo `
    'questionnaire_system.*' `
    '备份中的questionnaire_system目录'
```

本次迁移验证全部通过，因此没有实际执行回滚。
